# ICON-EU quantitative synoptic renderer

- **Live dashboard:** https://oliwertwister.github.io/read-sensor/
- **Repository:** https://github.com/oliwertwister/read-sensor
- **DWD ICON-EU GRIB2 source:** https://opendata.dwd.de/weather/nwp/icon-eu/grib/

`render_icon_synoptic.py` is the first quantitative numerical-weather-model pipeline in this project. It is distinct from the official static DWD chart viewer already present in the dashboard.

## Inputs

The renderer discovers the freshest complete ICON-EU regular-lat/lon field set and chooses the forecast lead whose valid time is closest to the current UTC time. It downloads four compressed GRIB2 fields:

- `T_2M` — 2 m temperature, converted K → `degrees_celsius`;
- `PMSL` — mean-sea-level pressure, converted Pa → hPa;
- `U_10M` — 10 m zonal wind component;
- `V_10M` — 10 m meridional wind component.

The regular-lat/lon ICON-EU product currently has a 0.0625° grid spacing. Longitudes are normalized from the source 0–360 convention to −180–180 before the Europe subset is selected.

## Processing stack

```text
DWD ICON-EU .grib2.bz2
        ↓
bz2 decompression
        ↓
cfgrib + ecCodes
        ↓
xarray DataArray
        ↓
coordinate normalization + Europe subset
        ↓
unit conversion
        ↓
Matplotlib contours / quiver
        ↓
EUMETSAT satellite background
        ↓
model/output/synoptic.webp + latest.json
```

Dask is intentionally **not** used in this first implementation. Each selected field is about one regular ICON-EU grid and comfortably fits in memory on the standard GitHub-hosted runner. Adding a Dask scheduler would add complexity and overhead without solving a current resource problem.

## Current visual product

The generated Europe overlay uses:

- white contours: PMSL isobars every 4 hPa;
- black contours: 2 m isotherms every 5 `degrees_celsius`;
- white arrows: 10 m wind vectors thinned to approximately 2° spacing;
- raster background: the latest EUMETSAT EUMETView MTG/FCI Geo Colour image already generated by the satellite pipeline.

The output metadata records the ICON initialization time, forecast lead, valid time, source URLs, contour intervals, and grid spacing.

## Interpretation and limitations

This is a model analysis/forecast overlay, not an observation. ICON-EU fields have finite model resolution and should not be visually interpreted as containing information finer than the underlying grid. The renderer contours the regular model grid directly; it does not upsample or smooth the meteorological fields merely to create a denser-looking map.

The wind arrows are visually thinned; that thinning is a display operation and does not change the underlying field. Satellite and ICON valid times are independently sourced and need not be exactly identical.

## Next technically useful extensions

Reasonable next fields include 850 hPa temperature, 500 hPa geopotential, relative humidity, precipitation, and cloud cover. A later version can export contour geometry as GeoJSON rather than only rasterizing it. Interpolation should be introduced only when a common target grid or point sampling genuinely requires it.
