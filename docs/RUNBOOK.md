# Operations and reproducible setup

Canonical production entry point: [`.github/workflows/pages.yml`](../.github/workflows/pages.yml).

Local runs can reproduce rendering/validation. Production R2 upload must run in GitHub Actions because the uploader uses a short-lived GitHub OIDC token.

## Accounts and credentials

| Service / credential | Register / configure | Stored as |
| --- | --- | --- |
| GitHub | https://github.com/ | repository + Pages + Actions |
| Cloudflare | https://dash.cloudflare.com/ | Worker + D1 + R2 |
| EUMETSAT Data Store | https://data.eumetsat.int/ | account |
| EUMETSAT API key | https://api.eumetsat.int/api-key/ | `EUMETSAT_CONSUMER_KEY`, `EUMETSAT_CONSUMER_SECRET` GitHub secrets |
| GitHub fine-grained PAT | https://github.com/settings/personal-access-tokens | Worker secret `GITHUB_ACTIONS_TOKEN`; repository-scoped, Actions: write |
| Cloudflare API token | https://dash.cloudflare.com/profile/api-tokens | only for headless Cloudflare automation; interactive setup can use Wrangler login |
| sensor bearer token | generated by `register-device.sh` | local mode-600 config; only SHA-256 stored in D1 |
| GitHub OIDC JWT | generated per Actions run | ephemeral; never stored |

DWD Open Data, Open-Meteo, Aviation Weather Center, OpenStreetMap and Natural Earth require no project API secret.

## First-time Cloudflare setup

```bash
cd worker
npm ci
npx wrangler login
npx wrangler d1 create read-sensor
npx wrangler r2 bucket create read-sensor-model-cubes
```

Copy the D1 `database_id` into `worker/wrangler.jsonc`. Keep the R2 binding name `MODEL_CUBE` synchronized with the bucket name.

Initialize D1:

```bash
npx wrangler d1 execute read-sensor --remote --file schema.sql
```

Configure the R2 bucket with the 14-day lifecycle recorded in `model/r2-lifecycle.json`, then verify the live rule in Cloudflare.

Store the scheduler PAT and deploy the Worker:

```bash
npx wrangler secret put GITHUB_ACTIONS_TOKEN
npx wrangler deploy
```

Worker cron and GitHub target variables are defined in `worker/wrangler.jsonc`.

## GitHub setup

Repository settings:

1. Enable **GitHub Pages → GitHub Actions**.
2. Add Actions secrets `EUMETSAT_CONSUMER_KEY` and `EUMETSAT_CONSUMER_SECRET`.
3. Keep `permissions: id-token: write` in `pages.yml`.
4. Keep Worker `GITHUB_OWNER`, `GITHUB_REPOSITORY`, `GITHUB_WORKFLOW` and `GITHUB_REF` aligned with the repository.

Do not store an EUMETSAT access token manually; EUMDAC exchanges the Consumer Key/Secret for access tokens.

## Run production

CLI:

```bash
gh workflow run pages.yml -f satellite_only=false
gh run watch
```

Web UI: **Actions → Deploy GitHub Pages → Run workflow**.

A full run tests frontend/Worker code, refreshes SYNOP, renders WMS + optional native FCI, renders ICON-EU + Zarr, uploads accepted model cubes to R2 through OIDC, builds the monitor, applies storage guards and deploys Pages.

Markdown-only pushes use the lightweight **Check documentation** workflow instead of the weather pipeline.

## Local validation

Match Actions with Python 3.13:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r model/requirements.txt
python -m pip install -r satellite/requirements-native.txt
npm ci --prefix worker
```

Fast checks:

```bash
npm test --prefix worker
node --check app.js
node --check model-map.js
node --check cube-storage.js
node --check cube-reader-worker.js
node --check data-monitor.js
node --check geometry-loader.js
node --check geometry-ui.js
node synop/test_decode.js
python model/test_metpy_diagnostics.py
PYTHONPATH=.:satellite python satellite/test_render_satellite.py
PYTHONPATH=.:satellite python satellite/test_history.py
```

Local rendering:

```bash
mkdir -p synop/output satellite/output model/output
PYTHONPATH=. python synop/update_live.py --catalog synop/stations.json --output synop/output/live.json
python satellite/render_satellite.py --output satellite/output

export EUMETSAT_CONSUMER_KEY='...'
export EUMETSAT_CONSUMER_SECRET='...'
PYTHONPATH=.:satellite python satellite/render_satpy.py --output satellite/output

python model/render_icon_products.py \
  --output model/output \
  --background satellite/output/geocolour.webp \
  --skip-zarr
```

Omit the EUMETSAT variables/native command to test WMS-only fallback. Omit `--skip-zarr` when inspecting a local Zarr cube. Use GitHub Actions, not a fabricated token, for production R2 upload.

## Sensor computer

Requires `osx-cpu-temp`, deployed Worker/D1 and authenticated Wrangler:

```bash
./register-device.sh sensor-node-01 \
  https://read-sensor-api.read-sensor.workers.dev \
  "$HOME/.config/read-sensor/collector.env"

./publish.sh
./install-schedule.sh
```

The LaunchAgent publishes every five minutes. The raw bearer token remains only in the protected local config.

## Verify a deployment

1. GitHub Actions is green.
2. `satellite/latest.json` is current and `satellite/history/index.json` has at most four snapshots.
3. `model/latest.json` exposes the current layer catalogue.
4. Worker `/api/v1/model-runs` lists recent retained R2 runs.
5. `monitor/latest.json` reports zero failed processing steps and storage below ceilings.
6. Live satellite/model selectors and point queries work without stale-cache artefacts.
7. R2 lifecycle and D1 retention are still configured.

When changing storage, cadence, time dimensions or product count, update monitoring/guardrails in the same change.
